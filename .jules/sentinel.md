## 2024-05-18 - [Fix Discord Ping Injection Vulnerability]
**Vulnerability:** The Discord REST client (`DiscordRestClient.cs`) and bot success service (`DiscordService.cs`) allowed ping injection vulnerabilities. The API wrapper hardcoded `parse = new[] { "users" }`, causing any arbitrary Discord user IDs embedded inside an untrusted string (like a player's character name) to actually ping that user in Discord.
**Learning:** Custom implementations of the Discord HTTP API don't inherit the strict defaults of official libraries (like Discord.Net) and must explicitly filter mentions. Developers using anonymous objects for JSON serialization missed how `parse` broadly evaluated everything rather than restricting it to a single user.
**Prevention:** When sending messages that mention specific users, pass an explicit allowlist in the `allowed_mentions` object via `new { users = new[] { targetId.ToString() } }` instead of using the `parse` property. Ensure reusable API wrappers accept and prioritize user-provided `allowedMentions` arguments.
## 2024-06-28 - [Fix Ghost Session Authorization Bypass]
**Vulnerability:** The `KickAccount` method in `GatekeeperService` only revoked the first matched session using `.FirstOrDefault()`. Since game accounts can have a 1-to-many relationship with active connections (e.g., multiple clients logged into the same account), this left subsequent active connections ("ghost sessions") authorized and unkicked even when the account was unlinked.
**Learning:** When revoking access or enforcing restrictions based on an external identity or account link that has a 1-to-many relationship with game connections, all matching instances must be explicitly enumerated and revoked. Relying on `.FirstOrDefault()` assumes a 1-to-1 relationship, leaving security gaps for multiplexed clients.
**Prevention:** When writing logic to revoke access for an account, always evaluate all matching sessions (e.g., using `.Where(...)`) and iterate through them instead of selecting the first match.
## 2024-06-29 - [Fix Gatekeeper Denial of Service for Server Passwords]
**Vulnerability:** A strict numeric length check intercepting `PasswordSend` packets caused a Denial of Service by incorrectly flagging legitimate 6-digit server passwords as custom PIN guesses. Legitimate users were given penalty strikes and eventually disconnected.
**Learning:** Broad validation logic for custom authentication flows (like numeric PINs) can inadvertently overlap with native application inputs (like server passwords) sharing the same format, especially when both rely on the same network payload fields.
**Prevention:** Explicitly evaluate input against known valid native configurations (e.g., `TShock.Config.Settings.ServerPassword`) to bypass custom intercept logic before applying strict format filtering or penalty tracking.
## 2024-07-02 - [Fix Ghost Session Authorization Bypass in HandleUnlinkAsync]
**Vulnerability:** The `HandleUnlinkAsync` method in `DiscordService` only revoked the first matched game account session using `.FirstOrDefault()` when unlinking a Discord account. Since Discord accounts can have a 1-to-many relationship with game accounts, this left subsequent accounts linked ("ghost sessions") authorized and unkicked even when the Discord account was unlinked.
**Learning:** When revoking access or enforcing restrictions based on an external identity or account link that has a 1-to-many relationship with game connections, all matching instances must be explicitly enumerated and revoked. Relying on `.FirstOrDefault()` assumes a 1-to-1 relationship, leaving security gaps for multiplexed clients.
**Prevention:** When writing logic to revoke access for an account based on an external identity, always evaluate all matching sessions (e.g., using `.Where(...).ToList()`) and iterate through them instead of selecting the first match.
